# Moonlight-qt (personal fork)

Public fork of `moonlight-stream/moonlight-qt`, kept for personal macOS builds and
video-latency experiments. Qt 6.11, C++ with Objective-C++ on the Apple renderers.
Upstream's own `README.md` covers building on each platform; this file covers what is
specific to the fork.

## Commands

```bash
qmake moonlight-qt.pro   # regenerate the Makefile (Qt 6.11, Homebrew qmake)
make -j$(sysctl -n hw.ncpu)
```

`Makefile` is generated by `qmake` and is not tracked as authored source. Editing it
is lost on the next `qmake` run — change `moonlight-qt.pro` or the `.pri` files.

## The fork's own work

Local commits add two video settings and the instrumentation behind them, concentrated
in `app/streaming/video/ffmpeg-renderers/vt_metal.mm`:

| Environment knob | Effect |
| --- | --- |
| `ML_PRESENT_CSV` | Logs on-glass present cadence at the `CAMetalDisplayLink` present point |
| `ML_PRESENT_BUFFER` | Sets the FIFO present cushion, in whole frames |

`PRESENT-BUFFER-FINDINGS.md` holds the measured results and the verdict. The companion
analyzer lives in the `play-telemetry` repo, under its `client_present` layer.

## Renderer scope decides whether a change is even reachable

The present buffer applies **only** to the VideoToolbox Metal renderer, which presents
through `CAMetalDisplayLink` with a latest-wins frame model. macOS defaults to the
libplacebo renderer on MoltenVK, which presents through a Vulkan swapchain and never
reads `presentBufferFrames`.

So a build that looks like it changed nothing usually was not running the modified
renderer. Choose **Metal** in Settings → Renderer before testing anything in
`vt_metal.mm`; the *Smooth frame delivery* setting is hidden otherwise.

## Important

- **Never commit personal issue templates, pull request templates, or CI workflows
  under `.github/`.** `.github/.no-distribute` marks this repo as opted out of central
  template distribution, and this is a public fork where such files would be visible
  as fork-specific noise.
- Keep local changes narrow and attributable. The fork carries a small, readable delta
  against upstream today; a broad reformatting or refactor makes every future upstream
  merge expensive to reason about.
- Measured claims belong in `PRESENT-BUFFER-FINDINGS.md` with the conditions that
  produced them. The renderer, the refresh rate, and the source frame rate all change
  the result, so a figure without them is not reusable.
